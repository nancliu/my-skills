# 多语言选型总表（项目落地版）

> 定位：新项目立项、技术评审、方案选型。维度：主场、GUI、并发、部署交付、生态短板、适合团队、典型场景、避坑提醒。  
> 参评：Ruby / Python / Go / Java / C/C++；补充：Rust / Kotlin。

## 决策规则（与 SKILL.md 一致）

1. 界面是交付重点、给普通用户使用 → **Python**
2. 核心是业务Web、需要灵活DSL、小团队快速迭代 → **Ruby**
3. 做平台/网关/agent、大量并发连接、要求交付简单、单二进制 → **Go**
4. 金融、强监管、核心交易、Flink流式计算、多人长期维护大型系统 → **Java（或Flink SQL规避手写Java）**
5. 碰硬件、驱动、内核、编解码、极致低延迟底层模块 → **C/C++**
6. 想要C的性能，又不想承担野指针风险，团队愿意啃陡峭学习曲线 → **Rust**

## 关键备注

- 流式计算：引擎底层是JVM；业务优先Flink SQL；复杂自定义算子Java/Scala；简单清洗可以PyFlink；Go/Rust一般只做上下游采集，不写核心算子
- GUI：所有语言里，**Python生态断层领先**；Ruby、Go、Java都属于“能用，但不适合把界面作为核心卖点”
- 分层混搭是工业常态：
  - 上层业务脚本/工具：Python / Ruby
  - 中台网关、采集服务：Go
  - 核心交易、实时流：Java + Flink
  - 音视频、硬件底层：C/C++
