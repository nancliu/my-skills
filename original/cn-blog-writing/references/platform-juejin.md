# 掘金平台写作惯例

## 读者画像
- 以工程师/开发者为主：能接受代码、表格、架构图，反感营销腔。
- 阅读动机：学方法、抄配置、评估方案。给"可复现"的东西。

## 结构惯例
1. **标题**：技术事实 + 结果（如"给 Claude Code / Codex 装上国产模型路由器：12 类任务 × 15 模型的可打分路由方案"）。
2. **TL;DR 要点块**：文章开头引用块给出 4–6 条核心结论，含关键词便于搜索命中。
3. **章节**：问题 → 方案 → 数据 → 架构 → 上手 → 开源。数字密集处用表格。
4. **代码**：安装/CLI/配置全部可复制命令块；架构用 ASCII 链路图或架构图。
5. **结尾**：给同行团队的实践建议（1-2-3 条），并引导到仓库提 issue/PR。

## 亮点处理
- 把最有冲击的数据独立成节（如"便宜 8~42 倍，能力只差 3%"），配表格。
- 每节一个动作；避免过程叙述（修 bug、踩坑、环境问题）出现在正文。

## 配图
- 封面：标题正下方，16:9 横版，信息图风格。
- 文内：架构图/矩阵图紧跟对应章节。
- 仓库横幅可放开源章节；发布时与 md 一起上传。

## 发布提示
- 掘金支持 Markdown 粘贴；图片逐张上传，顺序 = 插入顺序。
- 代码块注意语言标注（bash/python）。
