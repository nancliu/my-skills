# 技术要求/标准类内容编写

## 核心定位原则：约束下的差异化取舍

标准对象通常存在层级或类别划分（如按投资优先级、功能定位、规模档次划分）。**低层级或受限对象不是高层级对象的"缩小版"，而是"在约束下必须做出取舍的差异化场景"**。编写前先确立：

1. **对象定位**：对象在整体体系中的角色（如"接入与协同单元""执行层"）。
2. **支撑面**：本标准要保障的核心目标（如安全底线、互联互通），用"1) 2)"列明。
3. **约束**：投资、资源、规模、既有条件等约束，用数据支撑取舍判断（不同档位对象的投入量级不同，配置标准不可简单复制）。
4. **取舍判据**：把内容项按三级归类——**必做（安全底线/合规刚性，不计经济性）→ 宜做（投入产出可验证）→ 可暂缓（依赖特定条件或规模效益）**，正文以"应/宜/可"表达。

标准对受限对象的指导价值在于"告诉使用者**什么可以不建/不做**"，而非只列"应该做什么"。

## 编写流程

四阶段，详见 [references/workflow-verification.md](references/workflow-verification.md)：

1. **需求与约束调研**：收集实际投入数据与建设/实施内容清单，形成对照表；调研向"非标杆、受限条件"的对象和一线使用人员倾斜；产出三级分类结论。
2. **章节提纲**：先出提纲并多轮迭代定稿，再动正文；提纲阶段同步建立引用核查表（每个拟引文件核实现行性）。
3. **编写体例约定**：动手前先从参考文档提取体例（小节结构、编号体系、指标底线），形成约定文档并请用户确认。
4. **正文编写与修订交付**：逐章编写 → 格式/术语修订循环 → 结构审计与渲染核对 → 备份并交付。

## 格式纪律（硬约束）

详见 [references/format-rules.md](references/format-rules.md)。最常被审稿质疑的几条：

- 规范性用语只用 **"应/宜/可"**，不用"必配/宜配/可延后"等非标准口吻；**融入条款句子，禁止括注**"（应）（宜）（可）"。
- 标题层级 **≤4 级**（2.1 / 2.1.1 / 2.1.1.1）；条文编号用无括号数字"1 2 3"，冒号段二级用"1) 2)"；**禁止"（1）（2）（3）"格式**。
- **不允许悬挂节**：节首不悬置无编号内容；原"一般规定"性质内容并入具体条款或小节内。
- 标题不写冗余限定（如"（一般路段）"）。
- 参照式引用：**全称 + 标准号 + 章节条款**，不原文抄写；无文号文件按名称引用；引用前核查标准现行性。
- 表格编号连续；表格与条文内容重复时删表并顺延表号、同步改正文引用。

## 章节组织通用模式

详见 [references/chapter-structure.md](references/chapter-structure.md)。典型结构：

1. **一般规定**：适用范围、对象定义与定位、总体原则、分级/分档原则、数据与质量总要求。
2. **分专业/分对象章节**：按技术域或对象分章，每章设"功能要求"+"设备/设施配置"（或"功能配备"+"设备选型及布设"）两小节。
3. **特殊场景分列**：高风险、特殊条件场景单独成节；有专项文件覆盖的直接引用专项文件，不重复展开。
4. **衔接/接口章节**：与上级系统、关联方（平台、网络、外部系统）的衔接与数据对接。
5. **数据与安全收尾章节**：数据要素与质量、传输、共享交换、治理与安全。

建设期一次性内容（设计、建造、施工管控）与运营期分开，不混入运营期配置逻辑。

## 校验与交付

- 交付前必须：结构/格式审计（0 错误）→ 逐页渲染核对 → 目录更新（如用 Word 交付）。
- 每版交付前备份上一版；交付用 present_files，文件名保持交付名（不得改名为"xxx修改版"）。
- 多轮修订中用户常逐轮给出格式/术语修正指令，每轮都要重新回读文档并重建校验，不能凭记忆改。

## 编写风格

- 标准条文用陈述句，一条一款；量化指标给出具体数值与依据来源。
- 每条重要信息可溯源：来自用户材料、参考标准或可核查来源；无法核实的内容用占位或注明"待补充"。
- 参照底线类文件时取底线值；参照指南类文件提高要求时注明"参照《××》第×.×节"。
