# 标题命名方法（人话即标题）

技术博客标题唯一可靠的做法：**把作者本来会说的那句话放到封面上**。真实的人不会"造"标题，标题是从已经存在的表达里捞出来的。

## 核心原则

- 写标题前先问作者（或自己）：**"你平时怎么一句话跟人介绍这个项目/这篇文章？"** 那句话就是标题或标题的骨架。
- 真实对话里没人会说的句子 = 不合格标题。判断标准只有一条：把标题念出来，像不像一个人在跟另一个说话。

## 三个必须避免的"AI 味"方向

这三类是 AI 起名最常见的翻车形态，起名时逐条排查：

### 1. 工程化罗列（功能说明书式）

特征：堆砌参数、矩阵符号、功能清单，把标题写成文档摘要。

- 反面案例（真实）：`给 Claude Code / Codex 装上"国产模型路由器"：12 类任务 × 15 模型的可打分路由方案`（约 40 字，工程文档味）
- 病灶：读者要的是"发生了什么值得读的事"，不是功能列表。

### 2. 营销公式化（数字堆砌式）

特征：利益数字（省 X 倍/砍几十倍）、关键词堆砌、感叹号、承诺语气。这是套模板套出来的，读者一眼识别。

- 反面案例（真实候选）：`我把 Claude Code / Codex 接上了国产模型，账单省了 8~42 倍`
- 病灶：把"好处"直接喊出来，像广告；数字没有故事承载时反而廉价。

### 3. 口语模拟（造作比喻式）

特征：为了"像人话"而发明的说法——生造的动词组合、比喻、昵称，翻译腔。

- 反面案例（真实候选）：`给 Claude Code 装了个国产模型路由器`——"装了个路由器"不是任何人的真实说法，读起来像穿越剧台词。
- 病灶：在演口语，不是说人话。真正的口语是不经设计就存在的。

## 正确做法：从已有表达里捞

1. 让作者用一句话介绍项目（或问"你上周怎么跟同事说的？"）。
2. 把这句话原样放上，只做最小化修剪（删冗词、拆主副标题）。
3. 保留搜索关键词（技术词/项目名），但全文只出现一次，不堆叠。
4. 长度控制在 15~25 字；超过就拆主标题 + 副标题。

## 本次真实演进（可作为复现案例）

| 版本 | 标题 | 问题 |
|---|---|---|
| 初版 | 给 Claude Code / Codex 装上"国产模型路由器"：12 类任务 × 15 模型的可打分路由方案 | 工程化罗列 |
| AI 公式版 | 我把 Claude Code / Codex 接上了国产模型，账单省了 8~42 倍 | 营销公式化 |
| 口语模拟版 | 给 Claude Code 装了个国产模型路由器 | 造作比喻，穿越剧味 |
| **最终版** | **cn-llm-router：给国外 harness 配国内高性价比模型** | **作者原话，零改动** |

最终版来源：用户原话"cn-llm-router -- 给国外harness配置国内高性价比模型"（项目定位语），原文放上即标题。这条是最强证据：**定位语/一句介绍 = 标题**。

## 平台微调

- **掘金**：主标题可直接用定位语，技术关键词（Claude Code、Codex、国产模型）保持原词以便搜索命中。
- **知乎**：问题式标题可用同一句话改成陈述 + 第一人称（如"给国外 harness 配国内高性价比模型，我写了个 cn-llm-router"），保持口语长度。

## 起名检查清单（写完标题逐条对照）

- [ ] 这句话是作者本人会说出口的吗？（不是 → 重写）
- [ ] 没有功能参数堆砌 / 矩阵符号（×、×15 这类）
- [ ] 没有利益数字轰炸（省 X 倍、砍 X 倍、XX 实测）
- [ ] 没有生造的说法（装了个 XX、给 XX 穿上 XX）
- [ ] 技术关键词保留但只出现一次
- [ ] 15~25 字，超长已拆主副标题
