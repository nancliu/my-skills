# 标准国际会议参会报告编写规则（ISO/IEC TC 等）

配合 [`SKILL.md`](SKILL.md) 与 [`structure-and-figures.md`](structure-and-figures.md) 使用，适用于 ISO/IEC 技术委员会全会、工作组会议等国际标准化会议的参会报告与会间记录整理。

## 1. 文稿分层

| 类型 | 读者 | 允许内容 |
| --- | --- | --- |
| 会议记录（分会场） | 本人／团内供料 | 可保留 ASR 原貌标注、待核项、金句、情绪记录 |
| 全会／分会参会报告 | 院内领导与同事 | 章—节—段；决议与行动汇总；研判单独成章 |
| 对外／报部材料 | 主管部门 | 仅已核事实与正式口径；不写会场吐槽与内部研判 |

记录稿与报告稿分开维护；报告以记录稿为底稿重写，不直接剪贴条列。

## 2. 证据分层（会议特有）

| 层级 | 载体 | 用法 |
| --- | --- | --- |
| 一级 | 会议幻灯／截图原文、N 文件、ISO 门户 | 可直接引用原文，注明「会议幻灯截屏」 |
| 二级 | 录音逐字稿（经校核） | 可用，人名编号须与一级载体或官网校核 |
| 三级 | 智能总结、他人转述 | 仅作线索，不得直接作为事实写入 |
| 待核 | 无法确证项 | 集中列「待核清单」，逐项注明核验途径 |

- ASR 误识高发点：标准号（如 825321→25321）、人名（Franz Schober→误作 Frank Trovo）、机构缩写（acceptance by ISO/TC 211→误作「AI」）。凡遇编号、人名、机构，先对照幻灯截图与官网结构，再落笔。
- 会场口述的「决议请求（resolution request）」不等同已通过决议；行文用「提出决议请求／请求 TC 决议」，通过与否以 N 文件、投票与 OBP 为准。
- 东道主致辞、致谢等礼节内容一句话带过，不展开。

## 3. 结构（报告稿）

建议框架：会议概况 → 会议进展（按议程顺序，WG／AG 逐节）→ 跨委员会与专项通报 → 主要讨论与研判 → 决议与行动事项汇总 → 背景资料补充 → 附录（证据校正、待核清单）。

- 每一 WG／AG 一节，节内先中心段（该组本轮最要紧的 1～2 件事），再按「项目进展 → 决议请求 → 下次会议安排」展开。
- 决议数量多时用表；表前有判断段，表后不重复表内数字。
- 内部研判（政治动向、对我启示）单独成章，与事实章节分开，便于对外时整章摘除。
- 背景资料补充注明「公开资料，非会场内容」，与会议事实隔离。

## 4. 图表

- 幻灯截图是会议报告的主要图证：按「图 N-x」编号，图题注明来源性质（会议幻灯截屏／会场所排照片）。
- 决议、工作项清单用表；对照数字（参会人数、投票截止日）用表；叙述性内容用段。
- 「我的发言回顾」等笔记软件自动生成内容不可作为事实来源。

## 5. 会后动作

- 会期后 1～2 周内以 N 文件／OBP／ISO 门户核验决议编号与状态，将「待核」升级为「已核」或删改。
- 同一事项在不同场次（分会、全会、次日续会）的口径变化，以后者为准并回改前稿。

## 6. docx 排版样式（常用中文格式）

- 报告题目：黑体二号、居中；一级标题（章）：黑体三号加粗；二级标题（节）：黑体四号加粗；三级标题：黑体小四加粗；由 docx 段落样式实现，不使用全角空格占位。
- 正文：宋体（沿用模版默认字号），段首缩进 2 字符由样式实现；图题居中在图下、表题居中在表上；表格列宽按内容比例自动分配。
- 报告说明等元信息放配套说明文件，不进正文；正文以「提交人／提交时间」两行为止。
